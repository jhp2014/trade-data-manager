# UI 설계 논의

목말로 왔다갔다 하지 않고 그림으로 비교하기 위한 스킬. 기본은 **휘발성 위젯**이고, 사용자가 명시적으로 "저장해줘/남겨줘" 라고 할 때만 Artifact로 승격한다.

## 1. 시작 전 — 프로젝트 시각 언어 로드

placeholder 팔레트로 시안을 그리면 실제 화면과 안 맞아서 판단이 어긋난다. 매번:

- `apps/workbench/src/styles/theme.css` 의 `:root` 토큰(`--bg-*`, `--text-*`, `--border-*`, `--accent-*`, `--rise`/`--fall` 등) Read
- `apps/workbench/src/styles/palette.ts` 의 강약색(`STRONG`/`MID`/`WEAK`/`FAIL`) · 강조색(`ACTIVE`/`HOVER`/`FILTER`/`PIN`) Read
- 두 파일은 계속 바뀔 수 있으니 기억에 의존하지 말고 매번 Read로 최신값 확인

**알려진 UI 관용구** (필요한 경우에만 적용, 모든 시안에 강제하지 말 것):
- dockview 패널 헤더는 24px 고정, 헤더 컨트롤은 "더보기" 판 + 라벨 순환 패턴을 따름
- 정보 밀도는 HTS 스타일(고밀도 테이블/보드)에 가깝게 — 여백 넉넉한 일반 SaaS 톤은 이 프로젝트 결과 아님
- 다크/라이트 둘 다 고려 (`theme.css`의 라이트가 기본, 다크는 `prefers-color-scheme`/`data-theme` 대응)

## 2. 시안 생성 — 기본 3안, visualize 위젯

`mcp__visualize__read_me` (mockup 모듈)를 먼저 호출한 뒤, 요청받은 화면/기능에 대해 **서로 다른 방향의 3안**을 `show_widget`으로 띄운다. 색·톤·간격 차이가 아니라 **구조/배치가 다른 안**이어야 비교가 의미 있다.

- 발행하지 않는다 — 순수 대화 내 위젯, URL 없음
- 사용자 피드백에 따라 특정 안을 다듬거나 다시 3안을 내는 식으로 반복
- 이 단계에서 실제 컴포넌트 파일을 수정하지 않는다

## 3. Artifact 승격 — 사용자가 명시적으로 요청할 때만

"저장해줘", "이거 계속 참조하자", "댓글로 얘기하자" 같은 명시적 신호가 있을 때만:

1. `artifact-design` 스킬 로드 (디자인 투자 수준 판단)
2. 확정된 안(또는 비교하고 싶은 안들)을 파일로 작성
3. `Artifact` 툴로 발행 — 기본 비공개, 필요하면 사용자가 직접 공유
4. 이후 댓글 스레드로 피드백받는 흐름 안내 가능

**사용자가 명시적으로 요청하지 않았다면 이 단계로 넘어가지 않는다.** "괜찮아 보이네" 정도는 승격 신호가 아니다.

## 경계

이 스킬은 논의용이다. 방향이 정해져도 `apps/workbench` 실제 컴포넌트 코드는 스스로 고치지 않는다 — 사용자가 "이제 구현해줘"라고 명시하면 그때 별도 작업으로 넘어간다.
