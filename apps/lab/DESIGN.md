# trade-lab 설계

> 2026-10-12 · 대화로 합의한 방향의 정리. 바뀌면 덮어쓴다(이력은 git).
> 결정이 안 된 것은 맨 아래 「열린 결정」에만 둔다.

## 1. 목적

데이트레이딩에서 **비슷한 상황을 분류하고, 상황마다 어떤 대응이 어떤 확률로 통하는지**를 데이터로 찾는다.

사람은 판단은 잘하지만 그 판단을 규칙으로 말하지는 못한다(직접 로직을 만들려다 막힌 경험).
그래서 역할을 나눈다 — **사람은 판단(정답)을 주고, AI 는 그 판단을 설명하는 규칙을 찾는다.**

## 2. 학습 모델

| 지도학습 | trade-lab |
|---|---|
| 정답 라벨 | 사람의 **비교**(A 가 B 보다 낫다 · 비슷 · 못하다 · 비교 불가) + **근거·직감** |
| 입력 특징 | 스크립트가 계산한 수치(테마 대금, 확산, 순위, 매물 거리, 끼 …) |
| 모델 | **관점** — 비교 결과의 압축본. 사람이 읽을 수 있는 문서 + 계산식 |
| 검증 | 학습에 안 쓴 비교를 얼마나 맞히나(**일치율**) · 다른 달에서도 맞나 |

**선생님은 둘이다.**
- **사람 → 인지**: 이 테마가 강한가, 이 일봉이 좋은가, 누가 대장인가. 정답은 사람만 줄 수 있다.
- **시장 → 결과**: 이 상황에서 이 대응이면 통했나. 정답은 가격 흐름이 준다 — 사람 손이 필요 없다.

**비교로 받는 이유**: "좋다/나쁘다"는 말로는 스펙트럼이 안 담긴다. "이게 저것보다 낫다"는 사람이 일관되게 답할 수 있다.
**근거를 같이 받는 이유**: "대금이 두꺼워서" 같은 말이 AI 가 어떤 특징부터 볼지 알려 준다 — 규칙을 훨씬 빨리 찾는다.
**"비교 불가"도 정보다**: 대개 그 축이 아직 둘 이상으로 뭉쳐 있다는 신호다(예: 테마 강도 = 확산 + 대금 규모). 축은 미리 쪼개지 않고 비교 불가 이유가 나올 때 쪼갠다.

**자동화 준비도 = 축별 일치율.** 새 비교에서 AI 초안이 사람 판단과 꾸준히 맞는 축은 초안 확인을 생략하고 불일치만 본다.
"사람이 아무것도 안 해도 되는 날"은 축마다 따로, 숫자로 온다.

**규칙의 복잡도는 검증이 정한다.** 같은 정확도면 단순한 쪽. 복잡하게 해서 학습에 안 쓴 데이터·다른 달에서 실제로 더 맞힐 때만 복잡하게 간다.
조건을 자동으로 많이 뒤질수록 우연히 좋아 보이는 조건이 나온다 — 한 달로 찾은 결론은 다른 달에서 확인한 뒤에만 결론으로 올린다.

## 3. 학습 단위

축은 타점과 떼어 **자기 대상끼리** 비교한다. 타점은 나중에 자기 대상의 위치를 찾아 붙는다.
(비교 하나가 여러 타점에 쓰이고, 타점 없는 날·종목도 비교할 수 있다.)

| 학습할 것 | 대상(단위) | 정답의 모양 |
|---|---|---|
| **타점** — 어떤 매매인가 · 그 안에서 어떤 특징인가 | 종목 · 날짜 · 분 | 매매 종류 + 특징 설명(텍스트) |
| **테마 강도** | 테마 · 시각 (직전 흐름은 참고) | 두 대상 비교 + 근거 |
| **테마 내 대장** | 테마 · 시각 | 그 시각의 순서 또는 비교 + 근거 |
| **일봉** | 종목 · 날짜 | 두 대상 비교 + 근거 |
| **끼** | 종목 · 날짜 | 두 대상 비교 + 근거 |
| **기준선** | 종목 · 날짜 | 어디에 선을 긋는가 — tdm `chart_anchors` 에 약 7천 개가 이미 있다(그대로 정답지) |

**대상 표기**(라벨 파일·문서 공통):
- 테마 · 시각 — `반도체@2026-07-31T09:44`
- 종목 · 날짜 — `402340@2026-07-31`
- 자리(종목 · 날짜 · 분) — `402340@2026-07-31T09:44`

## 4. 라벨 — `labels/*.jsonl`

> 라벨·문서·AI 문답은 **별도 저장소 `trade-judgment`**(`C:\Users\whdgn\Dev\trade-judgment`, 로컬 전용)에 둔다 — 코드와 생명주기가 다르다
> (코드는 갈아엎을 수 있고, 판단은 쌓이기만 한다). trade-lab 에는 **규약**(zod 스키마 + 예시 파일)만 둔다. 저장소 규칙은 그쪽 README.

DB 를 쓰지 않는다. 사용자 한 명, 수천 줄짜리 텍스트라 DB 의 이점(동시 쓰기·대량 조회·조인)이 없다.
파일이면 AI 가 바로 읽고, **git 이 판단의 이력(= 관점이 자라 온 기록)을 남긴다.**

**JSONL** = 한 줄에 JSON 하나. 규칙:
1. **한 줄 = 라벨 하나, 고유 `id`.** 고치면 그 줄만 바뀐다(git diff 가 읽힌다).
2. **파일은 지금 상태만.** 수정 내역을 파일 안에 쌓지 않는다 — 이력은 git.
3. **줄 단위로만 쓴다.** 파일 전체를 덮어쓰지 않고, 바꿀 줄 하나를 읽고-고치고-저장한다. 화면과 AI 스크립트가 같은 모듈로 쓴다 — 둘이 동시에 써도 꼬이지 않는다.

파일 하나 = 라벨 종류 하나. 모양(필드 이름은 만들면서 굳힌다):
```
labels/테마 강도.jsonl  {"id":"…","a":"반도체@2026-07-31T09:44","b":"반도체@2026-07-15T09:34","rel":">","근거":"이만큼 강한 날은 잘 없다","확인":true}
labels/일봉.jsonl       {"id":"…","a":"402340@2026-07-31","b":"009150@2026-07-31","rel":">","근거":"","확인":false}
labels/타점.jsonl       {"id":"…","자리":"402340@2026-07-31T09:44","매매":"상한가 눌림","특징":"…","상태":"기록"}
```
- `rel`: `>` 앞이 위 · `≈` 비슷 · `<` · `≠` 비교 불가(이유는 근거에).
- `확인: false` = **AI 초안**. 사람이 확인하거나 고치면 `true`. 채점·학습은 `true` 만 쓴다.
  (초안 원본은 따로 보관하지 않는다 — 관점이 나아지는지는 "지금 관점이 확인된 비교 전부를 얼마나 맞히나"로 잰다.)
- 숫자(테마 대금·순위 등)는 라벨에 넣지 않는다 — 필요할 때 계산한다. 화면에 보일 수치는 초안을 만들 때 같이 계산해 보여 준다.

## 5. 문서 — `docs/*.md`

사람이 읽고 다듬는 글. AI 가 정리하고 사람이 검토한다.
- **관점** — 새 상황을 판단하는 기준. 비교 결과의 압축본. 축마다 보는 법 + 「눈금」(출처: 감 / 추출 / 임시) + 「기각」.
- **매매** — 매매 종류 하나에 문서 하나: **정의**(사람) · **대응 메뉴**(비교할 선택지 — 진입 위치 × 청산) · **가설**(A → B → C, B·C 빈칸 허용, 출처 자리, 상태: 추측 → 검증 중(n) → 지지 / 반박) · **데이터 결론**(AI, 늘 건수와 함께).
  "추측 조건"과 "탐구 질문"은 따로 두지 않는다 — 둘 다 A → B → C 모양의 가설이다.
- **열린 질문** — 아직 자리가 없는 것·답을 기다리는 것. 풀리면 지운다.

타점마다 떠오른 생각은 **타점 라벨의 텍스트**에 자유롭게 쓴다 — AI 가 거둬 매매 문서의 가설로 정리한다(같은 생각이 여러 자리에서 나오면 항목 하나에 출처만 늘린다).

```
├ server/     임시 판단 서버 — Vite 개발 서버 미들웨어 /judgment/*(명령 하나 · 포트 하나). tdm 이 이력을 내려 주면 은퇴
├ tools/      AI 분석 스크립트 + api.mjs(tdm api 통로 · 허용 경로 · .data 캐시)

trade-judgment/   (별도 git, 로컬 전용) — trading-review 의 후속: 판단 · 관점 · 분석 스크립트 · 작업 방식(CLAUDE.md)
├ 관점/       보는 법 노트 — 「당일 테마」 · 「테마 정리」 · 「테마 사전」(이력 이름 → 테마) …
├ 이력/       종목별 이슈 이력(<코드>.jsonl) — Claude 가 주도주시황 등으로 쌓는다. 형식은 이력/형식.md
├ 자료/       바깥에서 받은 원문(주도주시황)

```

```
화면 ──/api/*──→ Vite 프록시 ────────→ tdm api :3001      시장 데이터 — workbench 와 같은 길
화면 ──/judgment/*─→ 임시 판단 서버 ──→ trade-judgment/이력 · 관점/테마 사전   읽기만 — 메모리에 올리고 파일이 바뀌면 다시 읽는다. 화면은 judgment/ports.ts 창구만 안다
AI 스크립트 ──→ api.mjs ──→ tdm api                         분석 — 화면과 무관, 화면이 꺼져 있어도 된다
AI 스크립트 ──→ trade-judgment/이력 (tools/cafe/build.mjs)             이력 쌓기 — 화면은 다음에 읽을 때 새 파일을 본다
```

- **tdm 은 그대로 쓴다.** 시장 데이터(분봉 흐름 `/day-replay`, 차트 `/chart`, 테마 소속, 날짜, 종목명, 기준선 `/chart-anchors/all`, 라벨 `/groups`, 뉴스)는 tdm api 에 이미 있다.
  예외: **테마 단면 계산**(그 시각 전 종목 순위·테마 존 판정)은 tdm 에선 화면 쪽 계산이라 api 로 안 나온다 — trade-lab 이 직접 계산한다(trading-review `tools/cellset.mjs` 이식본 — tdm 앱 엔진과 결과 동일 확인됨).
- **AI 는 시장 데이터를 직접 읽지 않는다.** 분봉 원본은 너무 커서 스크립트가 특징값으로 요약하고, AI 는 요약을 읽는다. 넓게 훑기는 스크립트, 좁혀진 자리의 미묘한 판단(차트 모양 등)은 AI 가 직접.
- **캐시(`.data`)**: 한 번 받은 날은 다시 안 받는다. 1년치(거래일 250일)여도 압축 700~800MB 수준. 분석 스크립트는 하루씩 읽고 버린다. 원본이 바뀌면(수정주가 보정·늦은 수집) `--refresh`.
- **데이터 범위**: 분봉은 전 종목이 아니라 수집된 종목(하루 300~900개)만 있다.

## 7. 안전 — tdm 과 사용자 데이터를 지킨다

- **tdm 에는 아무것도 쓰지 않는다.** AI 는 `tools/api.mjs`(GET 고정 · 허용 경로만) 하나로만 tdm 에 닿는다.
  tdm api 에는 구글 시트 쓰기·Supabase 동기화·텔레그램 실시간 검색(요청 제한에 걸리면 워크벤치 뉴스까지 막힌다) 같은 위험한 길이 있다.
- **DB 직접 접근 금지**(market DB 는 사용자가 쓰는 한 벌) · tdm 폴더(`trade-data-manager`, `tdm-work`)의 파일·`.env` 를 건드리지 않는다.
- `tools/api.mjs` 의 허용 경로 목록은 AI 가 스스로 넓히지 않는다(사람이 고친다).
- 되돌릴 수 없는 git 작업(force push, reset --hard) 금지.

## 8. 이어받는 원칙 (trading-review 에서)

- **사후 정보 금지** — 판단·초안은 그 시각까지의 정보로만. 타점 후 뉴스는 결과 이해에만.
- **모순 = 판단끼리의 모순** — 수치가 비슷한데 판단이 다른 경우. 눈금과 다르다고 모순이 아니다.
- **눈금은 미리 박지 않는다** — 사람의 표현·비교가 어느 숫자 근처에서 나오는지 뽑아낸다. 통과/미달로 자르지 않고 숫자로 보인다.
- **결과는 숫자, 성공은 전략의 결과** — 자리마다 성공/실패를 매기지 않는다. 대응 메뉴를 씌워 잰다. 늘 건수(n). 1분 안의 순서를 모르면 불리한 쪽으로 가정.
- **사람이 고른 자리만 남기면 생존 편향** — 자동 후보 전체를 기록 대상으로 하고, 하루 전체 재검토로 놓친 자리를 보충한다.
- **사람의 글은 승인받은 것만 고친다** — 옮기거나 지울 땐 정확한 모습을 먼저 보인다.

## 9. 화면

모든 화면의 핵심: **AI 초안과 불일치를 먼저 보여 준다** — 사람은 가르칠 곳만 본다.

1. **축 비교** (먼저) — 두 대상을 나란히(두 시각의 테마 단면 / 두 종목·날짜의 일봉) + `>` `≈` `<` `≠` + 근거. AI 초안이 채워져 있고 사람은 확인·수정.
2. **타점 라벨링** — 분봉·일봉 차트 + 그날 후보 목록 + 매매 종류 · 특징 · 자유 텍스트 · 상태.
3. **기준선** — 기존 선을 읽어 학습 재료로 쓰고, AI 추천선과 사람 선이 다른 곳만 보여 준다.
4. **문서 보기** — docs 를 렌더링. 가설의 근거 자리를 누르면 그 자리 차트로.

화면 없이 먼저 할 수 있는 것: **기준선 학습**(정답 7천 개가 이미 있다).

### 화면 틀 — dockview + 경로

workbench 의 dockview 형태를 쓴다. 가져올 패널: **차트 · 테마 [복기](이 앱에선 "테마") · HTS뉴스 · 텔레그램**.
workbench 패널은 전역 기준점 하나(`focus`)를 따르지만, trade-lab 은 여러 상황을 나란히 본다 — 그래서 **경로**를 둔다.

- **경로** = 상황 하나 = `{ 종목, 날짜, 시각 }`. 사용자가 A, B, C … 로 계속 추가·삭제한다(색 하나씩). 경로의 상태가 곧 대상 표기(3절)다.
- **경로 줄엔 입력칸이 없다** — 날짜만 경로 줄에서 고른다(거래일 판: 년 | 월 | 그 달 달력, 분봉 있는 날만). 앞뒤 거래일 버튼은 실수로 눌리기 쉬워 두지 않는다.
  시각·종목은 패널 클릭이 쓴다(분봉 차트·뉴스 줄 / 테마 패널 종목 줄). 시각 미정은 `15:30`으로 보인다. 날짜를 바꿔도 시각은 그대로.
  **이름표(A·B) 클릭 = 그 경로를 활성**. **활성 경로 = 경로 색 고리**(접혀 있어도). 활성은 그 밖에 마지막으로 조작한 경로 · 펼친 카드의 빈 곳 클릭으로도 옮겨 온다.
  **펼침/접음은 카드에 마우스를 올리면 끝에 살짝 늘며 나오는 ▸/◂ 로**(활성과 따로, 저장된다).
  경로 추가·삭제는 설정 창 「경로」 칸(삭제는 확인 줄).
- **패널은 경로 하나를 구독한다**: `[활성]` | A | B | … — 패널 탭의 토글. `[활성]` = 마지막으로 조작한 경로를 따라간다.
- **비교 대상 수는 사용자가 정한다** — 같은 패널을 하나 더 열어(설정 창 「패널」) 탭의 경로 칩으로 경로를 다르게 걸면 2개·3개·4개 비교, 하나만 두면 단일 보기.
- **넘치면 스크롤 — 줄바꿈으로 아래로 내려가지 않는다.** 칩·카드·버튼이 늘어서는 줄(경로 줄·헤더 줄·칩 줄)은 넘치면 그 줄 안에서 가로 스크롤(`ui/ScrollRow`, 휠도 가로로).
  줄 높이가 내용·hover 로 바뀌어 아래 패널이 밀리면 안 된다. 고정 자리(⚙ 등)는 스크롤 영역 밖에 따로.
- **패널 탭** — 경로 칩(실선 채움 = 그 경로에 고정, 점선 = 활성을 따라감 · 글자는 지금 보는 경로) · 제목 · 탭 뒤 정보 · 최소화(마우스를 올릴 때만).
- **클릭은 그 패널이 보는 경로에 쓴다**(그리고 그 경로가 활성이 된다). `[활성]` 패널의 클릭은 그 시점의 활성 경로에.
- **패널을 고르면(탭·본문) 그 패널이 보는 경로가 활성** — 경로에 고정된 패널만(활성을 따라가는 패널은 이미 활성을 본다).
  기본 배치·화면 불러오기처럼 프로그램이 배치를 바꿀 때의 활성 패널 바뀜은 사용자가 고른 게 아니라 무시한다.
- **일봉의 다른 날짜 봉을 누르면 경로의 날짜 자체가 바뀐다** — workbench 의 "기준일 / 검색 날짜" 이중 층은 두지 않는다. 다른 날짜를 따로 보려면 경로를 하나 더 만든다.
  그래서 **일봉은 경로 날짜에서 끝난다**(그 날짜까지 2년) — 그 시각까지의 정보로만 보는 화면이다(8절 사후 정보 금지). 다른 날짜로는 경로 줄의 날짜 판이나 일봉 클릭으로 옮긴다.
- **테마는 경로에 없다** — 고른 테마는 카드 강조뿐이었고, 종목이 바뀌면 그 테마와 어긋났다. 테마 카드 머리를 누르면 그 카드 접기/펼치기.
  "선택 테마만" 보기를 만들 때 그 동작에 맞춰 다시 정한다.
- **테마 패널** — 경로의 (날짜, 시각) 단면(시각이 없으면 15:30). 그 시각까지의 값만 쓴다. 둘이다(같은 몸 `panels/themeBoard`, 소속만 다르다):
  「테마」(`htheme`) = **이슈 이력 소속** — 그날 **이전** 이력의 테마 전부(날짜 무관), 이력 이름은 trade-judgment 「테마 사전」으로 잇는다. 묶인 이력이 없는 종목은 「테마 이력 없음」 카드.
  종목 줄 **우클릭** = 그 종목의 이력 창(종목명 · 코드 · 시총 / 그날 장마감 정리 — 장중엔 볼 수 없는 정보 / 테마별 횟수 · 세부 이름 / 이력 줄).
  「시트 테마」(`theme` — 저장된 배치의 옛 테마 패널) = 시계열에 실려 온 시트 소속(지금 소속 — 날짜와 무관). 비교용, 시트를 걷을 때 같이 걷는다.
  유니버스 = 거래대금 상위 N ∪ 등락률 상위 N — **패널마다 즉석에서 바꾼다**(기본 80 / 40, 클라 계산이라 다시 받지 않는다).
  주도주(시총 5조↑ 3% 초과, 미만 5% 초과)·1분 신호(1분에 +0.6%p 이상 그리고 60억 이상)는 workbench 기준 그대로.
  workbench 에서 **뺀 것**: 복기 필터(매물대 조건이 그날 마감 고가를 읽는다 — 사후 정보) · 테마 배정 우클릭(tdm 에 쓴다) · 큐레이션 표시 · 즐겨찾기·수동 숨김
  · 포함관계 자동 숨김(카드는 전부 보인다) · 위 칩 줄(테마 바로가기·현재 종목 테마·1분 신호 테마 — 1분 신호는 카드가, 현재 종목이 카드 밖인 자리는 헤더가 보인다).
  카드는 접기/펼치기 두 단계(머리·분포 막대 클릭, 펼치면 주도주 · 틈 · 나머지). 머리 숫자 = 종목 수. 왼쪽 띠는 모두 실선(현재 종목 든 카드만 액센트).
  카드 아래 관련 테마: 겹침 = `테마 2/5`(이 카드에 함께 든 종목 / 그 테마 종목), 포함 = `[부모 N [자식 M]]`(각 테마 종목 수) — 수는 유니버스 기준. 종목 줄 사이엔 구분선이 없다 — 카드 안은 hover 바탕만, 평면 목록은 옅은 줄무늬.
  이 패널에서 고른 종목은 판이 제자리, 다른 곳에서 바뀐 종목은 그 테마 카드들을 맨 위 "현재 종목" 띠로.
- **HTS뉴스** — 경로의 종목·날짜 헤드라인(종목 / 전체 시황 토글, 키워드, 더 가져오기). 같은 날짜 뉴스 줄을 누르면 경로 시각을 그 뉴스 시각으로.
- **텔레그램** — **아카이브(tdm DB `/news/telegram/archive`)만** 읽는다. 경로 날짜가 바뀌면 그날 메시지를 저절로 읽고, 검색어로 거르고, [더보기] = 바로 앞 한 주씩(수집 범위 시작에서 멈춤). 수집 범위 밖의 날은 "언급 없음"이 아니라 "아직 모름"으로 표시.
  수집 범위(coverage)는 날짜마다 셋 — 빠짐없이 듦 / 일부만(수집 시작일 "HH:MM부터" · 수집 끝 날 "HH:MM까지") / 밖(범위 앞 · 아직 안 받음).
  coverage.from 은 방마다 가장 오래된 메시지 중 가장 늦은 것이라, 범위 앞이라도 메시지가 있으면 "일부 방만 수집된 날짜", 없으면 "수집 전".
  검색(q)은 본문 + 링크 미리보기(제목·설명)를 본다 — 검색어가 본문엔 없고 미리보기에서 맞은 메시지는 맞은 칸을 본문 아래 작게 보이고 강조한다(검색 중일 때만).
  다 안 든 날은 5분마다 다시 읽고(DB 라 싸다), 빠짐없이 든 날은 다시 읽지 않는다 — "오늘인가"가 아니라 수집 범위로 가른다.
- **사후 정보 표시(뉴스·텔레그램 공통)** — 경로 (날짜, 시각)보다 나중 항목은 흐리게 + "경로 시각 이후" 경계선(지우지 않는다 — 결과 이해용).
  분 단위(같은 분 = 이미 앎 — 테마 단면이 그 분봉까지 담는 것과 같다), 날짜를 넘어서도 잰다. 판정 함수는 하나(lib/pathTime).
- **메모리** — /day-replay 는 하루 ~23MB(안 쓰는 필드는 받자마자 버린다). 최근 본 날짜 4개만 남긴다(보고 있는 날짜는 수와 상관없이).
- 지운 경로를 보던 패널은 `[활성]` 으로 돌아간다. 경로 목록·패널 구독은 배치와 함께 저장된다.
- 나중의 비교 입력줄은 경로 둘을 골라("A vs B") 라벨을 남긴다.
- **라이브 텔레그램 검색은 쓰지 않는다**(2026-10-14) — `/news/telegram` 은 요청마다 개인 세션으로 텔레그램을 실시간 검색한다(GET 이라 읽기처럼 보이지만 외부 호출 · 요청 제한에 걸리면 워크벤치 뉴스까지 막힌다). tdm 이 메시지를 DB 에 모으게 된 뒤로 trade-lab 은 아카이브만 쓴다 — 부르는 횟수에 제한이 없다.

- **패널 이름엔 늘 번호** — "차트 (1)", "테마 (1)". 1번만 번호가 없으면 2번과 나란히 놓였을 때 비대칭이다.
- **패널 헤더 = 선언 → 공용 틀이 그린다**(workbench 「패널 헤더 재편」 방식) — 모든 패널(앞으로 새 패널도)이 따른다.
  패널은 정보(종목·날짜·건수 …)와 컨트롤(토글·선택·실행·팝오버)을 선언만 한다. 헤더 줄은 줄바꿈하지 않고(넘치면 가로 스크롤), 좁아져도 세로로 쌓이지 않는다.
  **컨트롤은 기본으로 전부 숨김** — 탭 줄 오른쪽 컨트롤 판에서 설정하고, **원하는 컨트롤만 핀으로 헤더 줄에 꺼낸다**(어떤 컨트롤이든). 정보는 기본 헤더 줄, 정보 판에서 숨김/탭/줄/바닥.
  꺼낸 배치는 패널 **종류** 단위로 남는다(차트 (1)에서 꺼내면 차트 (2)에도).
  **컨트롤은 헤더 줄에 나왔을 때의 모양도 스스로 선언한다** — 그래서 검색칸(입력 + 확정)도 컨트롤 하나다(판에도, 헤더 줄에도). 검색은 패널 본업이라 기본 자리만 헤더 줄.
- **최소화** — 탭의 − 는 창을 닫되 대장(열림 + 최소화)에 남긴다. 바닥 작업표시줄 칩으로 되살리고(구독·설정 그대로), 칩의 × 만 영구 삭제. 새 패널은 최소화한 패널의 번호를 빼앗지 않는다.
- **화면 저장** — 개수 제한 없이 이름을 붙여 저장하고, 원하는 화면에만 번호(Ctrl+1~9)를 짝짓는다(번호 하나에 화면 하나). 저장하는 것은 배치 + 패널마다의 구독·설정 — **경로(종목·날짜)는 넣지 않는다**(화면 = 어떻게 보느냐, 경로 = 무엇을 보느냐). 불러오다 실패하면 불러오기 전으로 되돌린다.
  화면 관리는 설정 창의 「화면」 칸, 바닥 작업표시줄엔 번호 붙은 화면 버튼만. 덮어쓰기·삭제·기본 배치는 그 자리 확인 줄로 한 번 더 묻는다(브라우저 confirm 안 씀).
- **설정 창(⚙ · Ctrl+,)** — 경로(추가·삭제) · 패널 열기 · 화면 · 차트(시각 이동 폭 · f 줌 봉 수) · 단축키 도움말을 한 창에. 경로 줄엔 경로 카드와 ⚙ 아이콘만.
- **단축키는 목록 하나**(workbench keymap) — 디스패처 하나가 정적 + 소유 훅이 얹은 커맨드를 돈다. 같은 키를 두 곳에서 등록하지 않는다.
  입력칸에 글자를 칠 땐 수식키 없는 키가 쉰다. **설정 창이 열려 있으면 창의 것(설정·도움말)만** — 창 뒤 화면이 몰래 바뀌지 않게.
  누르고 있기는 a/d 만 반복한다. 도움말은 목록에서 파생된다(설정 창 「단축키」 · ?).
  차트: **a/d = 활성 경로의 시각을 분봉 한 칸**, shift+a/d = 설정한 분(기본 20), f = 모든 차트 줌 토글(분봉은 그 경로 시각 가운데 N봉, 일봉은 경로 날짜까지 N봉).
  시각 선이 화면 가장자리를 넘으면 줌은 그대로 두고 선이 안쪽(폭의 30%)에 오게 옮긴다.
- **경로 우클릭 판** — 「다른 경로 가져오기」(그 경로의 날짜·시각·종목을 통째로) + 「기록」. 고르면 이 경로가 활성.
  기록 = 어느 경로에서든 본 (종목, 날짜) 최신순 최대 50(경로가 0.8초 멈췄을 때만 — a/d 연타 같은 중간 상황은 안 남긴다, 시각은 단위가 아니다).
  줄을 누르면 이 경로를 그 종목·날짜(마지막으로 보던 시각)로 되돌리되 **순서는 바꾸지 않는다**(목록을 차례로 훑을 수 있게). 줄의 × = 그 기록만 지움.
  (최근 탐색 패널은 없앴다 — 기록은 이 판에서 본다.)

**만드는 순서**: ① 빈 dockview + 경로 관리 + 패널 토글 ✓ → ② 차트 ✓ → (화면 저장·최소화·최근 탐색 → 지금은 경로 우클릭 기록) → ③ 테마 ✓ → ④ HTS뉴스 ✓ → ⑤ 텔레그램 ✓ → ⑥ 「테마」를 이슈 이력 소속으로 ✓(「당일 테마」 패널 · 사례는 걷었다 — 분류는 앱이 이력으로, 판단은 사용자가) → AI 문답(질문 → 비교 답 → 모음).
차트는 workbench 패널을 통째로 옮기지 않는다(깔때기·그룹·presence·체인 오버레이가 엮여 있다) — `DailyChart`/`MinuteChart` 부품과 데이터 훅만 가져오고 패널 틀은 새로 짠다.

  지금 tdm 이 정본이라 옮기면 정본이 둘이 된다 — 그 값을 어디서 읽고 쓰는지 정리한 뒤 따로 정한다.
- **문답 규약** — 질문·답·모음 파일의 필드. ⑥ 에서 정한다.

- **라벨 필드 이름·종류별 모양** — 만들면서 굳힌다.
- **대장 라벨** — 그 시각의 순서(삼성전기 > SK스퀘어 > 테스)로 받을지, 쌍 비교로 받을지.
- **일봉 축의 위·아래** — 초안: 매물 부담이 적고 과열이 덜한 쪽이 위.
- **끼 축** — 좋고 나쁨이 아니라 "끼가 큰(가벼운) 쪽이 위".
- **타점 상태·감 값** — `상태: 기록 | 아님`, `감: 할 만함 | 애매 | 별로` 에 사용자가 쓴 `패스` · `안함` 을 넣을지.
- **테마 소속의 날짜별 스냅샷** — tdm api 는 구글 시트의 *현재* 소속만 준다. 시트를 고치면 과거 테마 계산이 바뀌어 확인된 비교와 어긋난다 → 소속이 바뀔 때 스냅샷을 남길지.
- **상한가 눌림 규칙**(trading-review 열린 질문) — 자리 = 풀리기 직전 잠긴 분, 2차 풀림까지, 상한가 대비 1% 이하는 풀림 아님, 결과 = 끝까지 잠겼나/다시 풀렸나. 1분만 다시 잠긴 경우를 재잠김으로 볼지는 미정.
- **화면 프록시의 GET 외 차단** — 지금은 workbench 와 같은 프록시(차단 없음). 넣을지 나중에 정한다.
- **설정** — `.claude/settings.json`(7절 금지 항목 유지 · 개발 명령 허용) 내용.
